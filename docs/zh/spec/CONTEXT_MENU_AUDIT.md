# 右键菜单盘点与整理建议

按界面位置阅读现状、问题和建议，请先看[右键菜单：各处现状与调整建议](CONTEXT_MENU_REVIEW.md)。本文保留实现统计和源码依据。

盘点日期：2026-10-20，基于盘点时的工作树源码。本文是静态审计和后续整理方案，**不是已完成的界面改造或实机验收记录**。交互基线见 [UI_INTERACTION_CONSISTENCY.md](UI_INTERACTION_CONSISTENCY.md)。

用户确认的设计边界：参数面板与关键点编辑分别沿用 Cubism / Photoshop 逻辑，控件不同不构成交互冲突；Dock 标签组空白的“关闭全部”保留；图集通常不超过六页，目标页平铺并在超高时提供滚动条；普通网格右击操作当前选择保留。顶部菜单的信息组织与排列另列为优化项，不据此调整对象拾取策略。

## 1. 范围、口径和统计

覆盖 `src/main/kotlin/io/github/psd2live/ui/` 的自定义右键触发、菜单宿主、菜单内容、工具选项目录，以及没有右键入口的主要对象列表。没有读取模型样本，也没有改动产品逻辑。

“菜单宿主”指一处独立的触发状态与菜单渲染实现；同一宿主按对象类型切换内容、渲染任意多个条目、在多画布中复用，都不重复计数。因此，下面的 **17 是宿主数，不是屏幕上可以右击的位置数，也不是动态菜单状态组合数**。

| 项目 | 数量 | 口径 |
|---|---:|---|
| 已实现的自定义右键菜单宿主 | 17 | 清单 C01–C17 |
| 使用 `PressMenu` 的宿主 | 7 | C01–C07；其中 C04 按对象切换 ArtMesh / 参考图内容 |
| 直接使用 `TreeContextMenu` + `CompactMenuItem` 的宿主 | 8 | C08–C15；外观壳已共享，行与高亮没有按新约定统一 |
| 其他菜单壳 | 2 | C16 的 `TabStripDropdown`、C17 的自建 `Popup` |
| 右键有动作但没有菜单的控件 | 5 | R01–R05，不计入 17 |
| 建议优先补充菜单的模块 | 7 | M01–M07；现有功能已有入口，可复用业务能力 |
| 可选补充的模块 | 3 | O01–O03，不能直接视为缺陷 |
| 合理重复的入口组 | 8 | D01–D08；应保留快捷入口、统一定义 |
| 不合理重复或实现分叉 | 3 | U01–U03；其中只有 U01 是直接重复的鼠标动作 |
| 仍建议核对或调整触发的情形 | 4 | X01–X04；含待验证项，不把已确认保留的交互计入问题 |

普通输入框、可选择文本的系统/Compose 默认编辑菜单不计入自定义宿主。例如日志正文已有 `SelectionContainer`，不能据此断言“日志完全没有复制能力”。左键按钮弹出的选择器也不计为右键入口。

### 3.1 当前折叠策略

`MENU_ROW_BUDGET = 10`；至少三个成员的组才参与自动折叠，超过预算先折最大组，同样大小优先折后出现的组。创建、素材、镜像等标记 `alwaysFolds` 的组始终折叠。非横排的长选项也能折成二级。横排选择与变体使用分段控件，不按选项数展开成多行。

这个机制能控制长度，但同一组会随笔尖、目标、素材关联变化在一级/二级之间移动。建议固定任务分组，预算只作为溢出兜底；不要让高频动作随状态反复换层级。

### 3.2 目标顺序

1. 当前任务的确认/完成、撤回一步、取消；缺少目标的说明紧邻这些动作。
2. 工具变体/操作模式。
3. 高频值：大小/半径、强度或不透明度、硬度、角度、衰减/吸附等。
4. 与当前选择直接相关的命令。
5. 稳定二级组：选择、创建、拓扑、网格、素材、镜像、权重组；按当前模式只显示有关组。
6. 清空/删除等改变内容的动作在**所属组末尾**，与普通动作分隔。

特别要调整拓扑组中的“删除 → 复制”：复制移到普通编辑组，删除移到最后。确认/取消的工具会话语义保留，不能套用对象菜单的删除规则。

## 4. 素材库的内容与目标顺序

| 作用域 | 当前内容顺序 |
|---|---|
| 根目录、内容空白、树空白 | 名称 → 新建文件夹 → 导入文件 → 导入文件夹｜网格视图、列表视图、显示目录树 |
| 普通素材 | 名称 → 编辑 → 放置 → 替换所选图层（有目标）→ 添加参考图二级 → 调整分辨率（矢量）→ 定位引用图层（有引用）｜重命名 → 标签 → 默认作为参考图 → 移至上级（有父目录）→ 删除 |
| 文件夹 | 名称 → 打开 → 放置文件夹内素材 → 添加参考图二级（层内）→ 定位引用图层（有引用）｜重命名 → 标签 → 默认作为参考图 → 新建子文件夹 → 导入到此处 → 导入文件夹到此处 → 导出 PSD → 移至上级（有父目录）→ 删除 |
| “添加参考图”二级 | 单素材：背景、层内、前景；文件夹：仅层内。背景/前景标注不进入模型，层内标注进入模型 |

目标整理：

- 素材：编辑 → 放置/替换目标 → 添加参考图二级｜定位引用｜重命名、标签、默认参考状态、矢量分辨率｜移动｜删除。
- 文件夹：打开 → 放置全部/添加层内参考｜新建子目录、导入文件、导入文件夹｜重命名、标签、默认参考状态｜导出 PSD、移动｜删除。
- 根/空白：新建文件夹 → 导入文件 → 导入文件夹｜视图二级。网格/列表是互斥单选，“显示目录树”是独立勾选。
- 文件夹的“添加参考图”只有一个有效目标时直接写“作为层内参考图放置”，不为一个选项保留二级。
- “定位引用图层（N）”目前执行 `users.first()`，数量与实际定位范围不符。单引用直接定位；多引用改可选引用列表或显式“定位第一个引用”，不能把它算成已实现的批量定位。
- 移动目前只有“移至上级”；“移动到…”若新增需提供目录选择器，不能假定现有菜单已经支持任意目录。
- 删除禁用原因（图层/参考图引用数）应保留；文件夹动作需显示作用于后代素材的含义。

## 7. 重复：保留入口，消除分叉

### 7.1 八组合理重复

| ID | 重复入口 | 保留理由 | 应统一的内容 |
|---|---|---|---|
| D01 | 工具选项栏、顶部操作栏、主画布右键 | 操作距离不同，连续调节需要就近入口 | 已有 `ToolOptionCatalog` 是正确方向：值域、单位、步长、命令只定义一次 |

| D04 | 素材树、卡片、列表、目录空白 | 同一素材库有不同浏览方式，对象与容器作用域不同 | 继续共用 `MenuLine`/命令，不为每种布局各造一份菜单 |
| D05 | 动作行编辑/播放图标与右键编辑/播放 | 图标是高频快捷入口，右键补文字可发现性 | 同一播放状态、同一动作 ID、同一禁用规则 |

| D08 | 绘制顺序标尺右键短按与双击都打开数值对话框 | 同一精确编辑功能的快捷入口，右键拖动另有平移职责 | 保持短按/拖动阈值明确；若将短按改为小菜单，双击仍可直达数值框 |

快照左键应用与右键管理属于不同操作；Dock 标签和顶层工作区的关闭属于不同容器范围。它们不作为相同命令的重复计数，文案仍应明确“快照”“本组面板”“工作区”。

物理菜单的“恢复默认”和“删除”虽然都调用 `removePhysicsGroup`，**不是不合理重复**：`PhysicsGroup.overridden` 明确排除 `CUSTOM`，恢复是移除生成组覆盖，删除只对自定义组可用。应按来源区分可用项和文案，不合并为一个含糊的删除动作。

## 9. 逐模块目标顺序与层级

本节是建议目标，不代表当前实现。`｜` 是分隔；“…”表示打开窗口/对话框；一级尽量不超过现有工具菜单的 10 行预算，标题/说明与内嵌控件也计入高度。

| 模块 | 建议目标结构 | 二级与控件 |
|---|---|---|
| ArtMesh 树 | 名称 → 类型转换｜显示/隐藏、独显｜创建 → 网格 → 绘制顺序…｜导入到此处…｜删除图层 | 创建：父曲面/父旋转/路径/摆动；网格：重建/独立网格拆分/前后景拆分，按有效能力显示；绘制顺序的重置放同一相关组 |
| 变形器树 | 名称｜创建 → 摆动…（适用）→ 导入子图层…｜展开/折叠｜删除当前/删除链… | 创建用二级；当前/链作用域必须先定，再对齐选择高亮和文案 |
| 参考图 | 名称 → 转换（适用）｜显示/隐藏 → 不透明度 → 锁定（适用）｜显示位置 → 参数钉选｜移除 | 显示位置使用单选二级并显示当前值；钉选二级保留轨道/二维板与清除，支持持续操作 |
| 参数文件夹 | 名称｜新建子参数、新建子文件夹｜重命名、标签颜色｜删除文件夹 | 颜色二级：无色、预设色块、自定义…；危险程度按删除是否仅移除目录/是否影响成员判断 |
| 参数快照 | 应用 → 用当前值覆盖 → 重命名｜删除 | 3–4 个动作平铺，不需要二级；覆盖需要明确当前参数值来源 |
| 动作 | 编辑 → 播放/暂停｜重命名（自定义）、复制/复制为自定义｜恢复默认（内置且有修改）｜删除 | 保持平铺，恢复与删除不同组；无效操作禁用并说明 |
| 物理组 | 重命名 → 复制 → 编辑摆动（适用）｜上移、下移｜恢复生成值（有覆盖）/删除自定义组 | 无需二级。启用状态可由原复选框保留，不必再添加重复设置表单 |
| 模拟体 | 烘焙/重新烘焙 → 清除烘焙｜删除 | 维持短菜单；重命名等管理能力先核对需要，不为了对称盲目添加 |
| 图集图块 | 所选名称/数量 → 聚焦所选｜密度与旋转操作 → 各目标页｜锁定/解锁｜排列所选 → 替换图像（单选） | 通常不超过六页，移页目标继续平铺；超出可用高度时显示滚动条；密度与旋转是否分层按整体布局评估 |
| 图集空白 | 页名｜全选本页 → 适配本页｜排列全部｜保存当前页… | 不受是否还有其他选中图块影响其“当前页”作用域 |
| Dock 标签 | 面板名｜浮动/返回停靠｜关闭当前、关闭同组其他、关闭本组全部 | 不显示与当前面板类型不符的画布关闭文案；关闭范围写明 |
| Dock 组空白/握柄 | 关闭全部 | 保留单项组菜单，不要求扩充或撤销入口 |
| 顶层工作区 | 工作区名｜重命名、复制｜关闭工作区、关闭其他工作区、关闭右侧工作区 | 维持平铺；全局页面标签是否可关闭按现有约束 |
| 最近文件 | 打开/生成 → 显示所在目录｜移除最近记录 | 维持平铺；不增加删除磁盘文件 |
| 日志表头 | 时间、来源、标签三个独立勾选｜恢复默认列布局 | 独立开关不互斥；连续勾选不关闭菜单，重置后关闭 |

## 10. 二级菜单与控件整理

### 10.1 二级菜单的具体问题

| 问题 | 已确认实现/限制 | 整理要求 |
|---|---|---|
| 动态折叠改变位置 | `foldedGroups` 随工具内容和行数改变层级 | 创建、网格、素材、镜像等保持固定层级，大小/强度等高频控件固定一级 |
| 图集菜单超出可用高度 | 图集为每个目标页生成一个一级 `CompactMenuItem`，通常页数不超过六页；容器没有统一滚动保证 | 保留平铺，限制到可用高度并提供滚动条；不因存在多页强制增加二级 |
| 二级禁用状态缺接口 | `FloatingMenuSubmenuRow` 没有 `enabled`；参考钉选在编辑忙碌时仍可开空闲浏览壳，素材二级也可能全部子项禁用 | 区分“允许只读查看”与“无可执行子项”；需要禁用时支持统一视觉和命中规则 |
| 二级容器没有统一滚动 | `MenuSecondLevel` 仅 `heightIn(max = 540.dp)`，普通 `GlidingColumn` 不滚动；参考钉选内部另有 340dp 滚动 | 在共享层处理视口约束和滚动，不依赖每种子内容自行补齐 |
| 键盘导航未形成完整约定 | 二级 Popup 为 `focusable = false`，行只提供点击/悬停；未见统一上下/左右、Home/End、Esc 层级导航 | 补共享焦点/活动项模型；方向键开关二级，Esc 先关二级再关一级，Enter 执行动作。不能只把 Popup 改成可聚焦 |
| 悬停立即打开与跨区关闭 | `FloatingMenuSubmenuRow` 悬停即 `onOpen`；一级进入其他行即关二级 | 按共享 Motion 档位评估延迟/跨区容错；实测边缘向左展开、斜向进入和窄窗口，避免误收起 |
| 名称很长 | 多处固定 236dp，子级有 196dp，文本单行省略 | 按现有令牌与四语言测量，保留必要 ID/完整名称提示；固定宽度不是要求用户猜被省略的操作对象 |

### 10.2 控件选择

| 数据语义 | 应使用控件 | 现状与改进 |
|---|---|---|
| 一次性命令 | `FloatingMenuRow`，可带图标/快捷键 | 将旧 `CompactMenuItem` 右键内容迁移，危险行单独分隔；不为所有普通命令强加图标 |
| 互斥选择 | `FloatingMenuRadio` 或短分段控件 | 参考显示位置、素材网格/列表改明确单选。不能仅靠强调色竖条表达互斥关系 |
| 独立开关 | 菜单勾选/共享开关行 | 目录树显示、日志列显示、锁定等；混合多选状态应有混合标记，不能把“部分锁定”画成全关 |
| 连续工具设置 | `FloatingMenuSlider` + 数值显示；精确输入可用共享数值编辑 | 当前滑条右侧只是文本，不能精确键入。大小/半径保留对数映射、单位和键盘步长；短菜单不塞完整检查器 |
| 文档连续编辑 | 预览 + 一次结束提交 | 参考不透明度已有 `previewReferenceOpacity`/`commitReferenceOpacity`；应验证关闭/失焦/取消时终结会话。工具临时设置不必写文档历史 |
| 色彩分类 | 有名称/提示的色块 + 自定义… | 参数文件夹预设色应有可访问名称/选中状态，单独的自定义颜色窗要明确提交/取消；不能只凭颜色判断 |
| 参数钉选 | 专用轨道/二维板 | 保留，属于明确任务控件；不把它展开成数百个参数值菜单行。禁用、滚动和批量连续操作需完整 |
| 大量目标选择 | 带搜索和滚动的选择器 | 轨道参数、物理参数、目录、目标页很多时使用。左键选择器维持左键，不强制改为右键 |
| 状态/禁用原因 | 标题、说明、尾部提示 | 非动作不参与滑动高亮；快捷键尾列与状态尾列区分，快捷键从 `keymap.labelFor` 读取 |

### 10.3 共享壳与动作生命周期

- 右键统一到 `PressMenu + GlidingColumn + FloatingMenu*`；共享单条 `MenuGlide`。直接使用 `TreeContextMenu` 的调用点不能视为已经完成统一。
- 高度应受可用窗口限制并可滚动：`PressMenu` 当前有 560dp 上限，`TreeContextMenu` 默认没有高度/滚动保证。固定 dp 上限还需验证小窗和高缩放。
- 记录触发点并转换到菜单宿主坐标。Dock 和工作区标签目前没有记录鼠标坐标；折叠变形器链名字片段把**片段局部坐标**直接写入行菜单位置，应转换成行/宿主坐标后再使用。
- 普通动作先关闭再执行并按所属面板恢复焦点；打开对话框/窗口的动作保留新窗口焦点，持续调节保留菜单。现有工具菜单有 `keepsMenu`/`opensDialog` 与 `invokeMenuAction`，其他菜单应复用同一规则。
- 不把所有动作都粗暴送回主画布：重命名保持输入焦点，动画保持时间线，辅助快照管理按其面板处理。
- 动作可用性同时覆盖业务能力、选择类型、当前工作区、后台任务/草稿状态和回调存在性。ArtMesh/变形器创建当前只判 `editable`，调用是可空回调；应检查接线，避免可点击但无动作。
- 右键优先级统一为：控件已消费 → 当前手势/鼠标绑定 → 本上下文菜单。打开菜单不应提交编辑、删除对象或改变姿态。
- 多选中右击已有成员保留集合，右击未选对象按约定切换；菜单需说明命令是单对象还是全部所选。层级当前会保留部分多选外观，但 ArtMesh 行命令仍针对该行 ID，不能让用户误判为批量。
