# 网格拓扑与图层拆分

[文档目录](../../README.md) · [PSD 素材与命名](PSD_LAYER_SPEC.md) · [画布编辑](../guide/CANVAS_EDITOR.md)

本页说明自适应网格如何从图层 Alpha 生成、边缘模式与内部填充算法的区别，以及导入时与编辑器中的图层拆分方式。

## 生成流程

`AdaptiveMeshGenerator` 从图层 alpha 建立轮廓。预处理先消除边缘噪点，再追踪外轮廓与孔洞；Bezier 采样决定轮廓顶点，`maxEdgeDistance`（界面中的“边缘点距离”）控制其间距。窄形状可生成带状网格。

### 描轮廓的分辨率

所有长度（设置值与生成器自身的像素容差）都以网格单位计（`MeshResolution`，`meshUnits`）。生成器在“工作像素”上运行：每网格单位 `detail` 个工作像素，栅格先按最大 alpha 缩减到工作分辨率，因此任何画过的像素都不会在缩减中消失。边缘点距离、外边缘距离、内部密度和各容差都乘以 `detail` 换算成工作像素，所以顶点密度只由网格设置决定，与栅格分辨率无关；只有轮廓本身更贴近原图边缘。

`meshTrace`（网格面板“按贴图像素描出轮廓”）决定描轮廓所读的栅格：

| 取值 | 读取 | `detail` |
| --- | --- | --- |
| `TEXTURE`（新工程默认） | 密度高于画布矩形的图层读其贴图本身：先把浮点矩形折算进去、按原密度铺到整数边界（`CanvasDensity.alignedRaster`），再按最大 alpha 缩减；其他图层读其栅格 | 栅格所能提供的最细值：至多 `MAX_DETAIL`（4），工作像素至多 `MAX_WORKING_PIXELS`（1 MP），不低于 1 |
| `CANVAS`（此前保存、没有该字段的工程） | 画布分辨率视图 `CanvasDensityLayer`（面积平均到每画布单位一像素） | 1 |

例如 1024² 贴图放在 64 单位矩形上：`CANVAS` 先平均成 64²，细于一个画布单位的睫毛 alpha 被摊薄到阈值以下，网格把它们切掉；`TEXTURE` 在 256² 工作分辨率上描轮廓，睫毛留在网格内，顶点间距仍按 64 单位的设置。没有更多像素可用的图层（画布分辨率栅格、`PIXELS` 单位或 2048 以内文档）两种取值得到逐位相同的网格。两轴密度不同或贴图稀于网格单位时，`TEXTURE` 也读画布视图。

### 包裹拓扑

`TEXTURE` 描出的是真实绘制边缘：一排睫毛、发梢或指尖各自成为一段凸出的轮廓，顶点随之成倍增加（例如带九根睫毛的眼睛约 120 个顶点）。Live2D 制作中这类细小凸起通常随同一个简单包络一起变形，因此网格设置提供“包裹”（`MeshSettings.wrap`，全局默认 `meshWrap`，单位为网格单位，0 为关闭，默认 0），两种 `meshTrace` 均可使用。

`MeshWrap` 在描轮廓之前对工作像素上的遮罩做形态学闭运算：先按半径 r = `wrap` / 2（换算为工作像素：`wrap × detail / 2`）膨胀，再以同一半径腐蚀。宽度小于 `wrap` 的缝隙、凹口和孔洞被填满，凸起的尖端保留，所以睫毛连成以尖端为边的扇形包络；比 r 长的细笔画完整留在包络内，不会被截断。闭运算结果是原遮罩的超集，补入的像素记为不透明、原有像素保持原 alpha，因此任何绘制像素都不会落在网格外。膨胀和腐蚀都是对精确欧氏距离变换（Felzenszwalb–Huttenlocher 抛物线下包络，按列再按行）取阈值，耗时与像素数成线性、与半径无关；栅格四周按半径补透明边，贴边的像素不会被腐蚀掉。凸形图层闭运算不增加像素，网格与关闭时逐位相同。

半径过大也会把本应分开运动的部分合并，例如手指间距小于 `wrap` 时手指会合进一个包络；对整组部件使用全局值，对个别部件用单层覆盖。

| 合成示例（`MeshTraceTool.wrap`） | 0 | 4 | 8 | 16 | 32 |
| --- | --- | --- | --- | --- | --- |
| 九根睫毛的眼睛（1024² 贴图 / 64 单位） | 124 | 122 | 110 | 41 | 29 |
| 头发细束（1024² / 128 单位） | 224 | 245 | 180 | 83 | 58 |
| 张开的手（512² / 128 单位） | 100 | 104 | 74 | 61 | 58 |

表中为顶点数。闭运算在 512² 工作栅格上约 6 ms，与半径无关；顶点减少后后续构网更快，睫毛示例整体耗时反而下降。

网格缓存 `PreviewMeshCache` 以栅格摘要、阈值、设置、单位与 `detail` 为键，同一键只生成一次（并发请求等待同一次生成），不同键可并行：生成 Rig 时先在后台线程池上并行生成各图层的网格，足迹与网格阶段随后直接命中缓存。生成器是纯函数，生成顺序不影响结果。

## 边缘模式

“轮廓位置”决定轮廓附近放几圈顶点：

| 模式 | 顶点排布 | 位置参数 |
| --- | --- | --- |
| 单层边缘 | 一条轮廓线 | “外边缘距离”：轮廓向外偏移的距离 |
| 双层边缘 | 两条错位的包络线夹住原始轮廓 | “边缘网格宽度”：两线的总间距 |
| 三层边缘 | 中线贴合原始轮廓，外线和内线各距中线一个宽度 | “边缘网格宽度”：外线或内线到中线的距离 |

![同一张脸分别使用单层、双层、三层边缘生成的网格](../../imgs/mesh-edge-modes.webp)

*从左到右：单层、双层、三层边缘。多层边缘在轮廓处留出窄带，适合需要沿边缘弯折或做描边形变的部件。*

外层的点可以超出图层像素范围，其 UV 外推到透明区域，与手工放置的顶点一致。

## 内部填充

每个连通域先按轮廓约束耳切，再按所选算法放入内部点，随后进行受约束 Delaunay 翻边与过长内部边细分。轮廓边及孔洞边始终是受保护的边，最后检查边使用次数和 Euler 关系；无效结果由恢复路径处理。“内部密度”（`interiorDensity`）控制内部点距，点数受预算限制。

| 算法 | 特点 | “内部密度”的含义 |
| --- | --- | --- |
| 渐疏泊松填充（默认） | 按到轮廓的距离连续增大点距，在抖动候选格上做确定性的可变半径泊松筛选；边缘支撑点多、内部渐疏，没有成片的栅格痕迹。可调“边缘过渡倍率”“渐变斜率”“随机度” | 最大点距 |
| 平衡四叉树填充 | 直角三角逐级二分的米字格，向内逐级变疏；相邻格最多差一级（4-8 细分） | 最粗一级格距 |
| 正三角分形细分 | 正三角形逐级四分，相邻最多差一级 | 最粗一级格距 |
| 轮廓层铺 | 沿轮廓向内逐层铺设行并按 2:1 抽稀，中心用正三角点阵收尾 | 中心点距 |
| 简单三角填充 | 均匀错列的三角点阵，作为兼容选项保留 | 点距 |

## 连接拓扑

“抑制边缘点之间的跨越连线”默认关闭。轮廓上相邻顶点仍须相连，才能闭合图层边界。开启后，对非相邻轮廓顶点之间的内部对角线，算法先尝试翻成连接内部顶点的边；无法翻转的对角线在边上插入一个内部顶点。此约束只作用于单层轮廓的三角化；多层边缘的内侧行属于内部支撑行，允许它们之间连接。如果约束导致平滑轮廓构网失败，同一轮廓会先以普通拓扑重试，避免退化为锯齿状像素轮廓。

## 两种拆分路径

- **旧工程的左右部件**：导入时不再自动拆分，新图层保持完整，需要时用下面的编辑器拆分。较早版本在导入时用 `ComponentSplitter` 按生成网格的连通域把双侧图层拆成 `:r` / `:l` 虚拟部件；工程的设置或编辑仍引用这些 ID 时，分析照旧把该图层拆开以保留它们（`Analyzer.expandLayer`）。
- **编辑器“按网格拆分”**：`MeshComponentSplit` 用当前屏幕网格的三角形连通关系确定部件。若各网格岛在 X 或 Y 轴上可分开，直接按岛间分界线分配源像素；否则先用实际三角形覆盖区域标记归属，再扩散到抗锯齿边缘和未覆盖像素。部件保存为独立图层并取代原图层：原图层离开源图，部件网格取自拆分时原网格的对应部分，连同其关键形、混合形、路径、权重与 Glue 写入 `art_primitive` 记录（见[文档层](DOCUMENT_LAYER.md#拆分物化画元记录-art_primitive)）。之后修改部件的网格设置时再按其像素重新生成网格并迁移这些绑定。

编辑器另有不依赖网格连通域的拆分：多边形拆分（`source_split_polygon`，按画布多边形切成内部与余部）与前后分层的深度拆分（`source_split_depth`），同样以 `art_primitive` 部件取代原图层；导入 CMO3 模型的拆分沿用旧记录。记录与重放规则见[文档层 · 拆分物化](DOCUMENT_LAYER.md#拆分物化画元记录-art_primitive)。

编辑器拆分保留所有非透明源像素，避免把相邻图层的边缘像素分错。已经保存的拆分图层拥有独立像素数据，修改算法后需要从原图层重新拆分才能更新其归属。

## 手工拓扑编辑

自动布点之后的逐点修正都记为 `canvas_topology` 作者日志（GUI 与 MCP `canvas` 的 `topology` 分支共用），拓扑本身由 `org.umamo.edit` 的纯函数决定，编辑器提交前用同一函数预判结果与选区（`CanvasTopology`）：

| 动作 | 纯函数 | 新顶点来源 |
| --- | --- | --- |
| `add_points` | `MeshManualOps.addPoints`：逐点定位（三角形内 1→3、边上拆边、网格外从最近可见轮廓边扩一个三角形），之后在新顶点周围按下文的翻边规则向 Delaunay 翻边 | 原顶点的仿射组合（`WeightedOf`，权重和为 1） |
| `delete_edges` | `MeshManualOps.deleteEdges`：只删所给的边：内部边在其四边形内换对角线（四边形在任一形状中不凸则拒绝），轮廓边删去所在三角形并删除不再使用的顶点；产生点接（一个顶点的三角形分成两扇）或删光三角形时整批拒绝 | 保留顶点 `FromOld` |
| `retriangulate` | `MeshManualOps.retriangulate`：在所给顶点周围（为空则全网格）按下文的翻边规则向 Delaunay 翻边 | 不变 |
| `merge` / `duplicate` / `connect` / `delete` / `subdivide` / `split` / `knife` | `MeshTopologyOps`、`MeshRefinementOps` | 各操作自身给出 |

翻边规则（`MeshShapes`）：一次翻边把四边形的两个三角形换到另一条对角线，只有四边形在静止形、每个关键形格（静止形加其增量）和每个混合形中都严格凸时才翻，否则摆到某个姿态时新三角形会重叠翻面；判断时不看两个三角形的绕序，新三角形沿用被替换三角形的绕序，绕序不一致的网格也能编辑。`add_points` 与 `retriangulate` 另外要求第四个 UV 落在其余三个的仿射映射上（贴图不动），并在网格默认姿态下的画布空间（世界坐标）用按四边形尺寸归一化的外接圆判定 Delaunay，Warp 下非等比的局部空间不影响判断。判定空间只求该网格、与它粘合的网格及它们的父变形器链，参数取默认值；因此翻边结果依赖父链、粘合与参数默认值：基础 Rig 重新生成、父变形器、粘合或参数默认值改变之后，重放同一条日志可能得到不同的三角化（顶点集合与贴图不变，只是对角线不同）。翻边用带边队列的 Lawson 算法，每次翻边常数时间，只把四边形的四条外边重新入队。编辑器提交前用同一函数预判选区与拒绝原因；超过 3000 个三角形的网格不预判，直接交给后台提交。

结果须是合法三角化（`MeshManualOps.isLegal`）：每条边至多两个三角形使用、每个顶点都被使用、无重复角点或零面积三角形。原本不合法的网格（旧导入）只要求操作不再新增问题。

这些操作都知道每个新顶点由哪些旧顶点按什么权重得到，因此直接以 `VertexSource` 经 `withMeshTopologyEdit` 迁移关键形、混合形、顶点组与 Glue（被删顶点的 Glue 对随之删除），并在同一步重新绑定路径；比 `RasterMeshJournal` 从位置推断来源（最近点或重心坐标）更精确。整体替换网格（按像素重建、绘画扩展、按纹理结构重布点）仍走 `RasterMeshJournal`。

带内部造型的网格：`WorkspaceDocumentEdits.journal` 比较本批日志前后目标网格的 `InteriorMeshStamp`（拓扑与静止形），造型在改动前与网格一致、改动后不一致时，在同一候选中按新网格重新烘焙（与结构重布点相同），与改动它的是哪种命令无关。烘焙失败（面积检查或其他烘焙错误）时编辑照常提交，造型保留配方并报告 `interior.issue.mesh`；取消不会被当作烘焙失败吞掉。

## 设置流向

网格面板「全局默认」中的边缘模式、填充算法和拓扑开关是全局默认值；在网格工作区选中部件后，右侧“网格”面板可按部件覆盖，点“确定”后生效。

![在网格工作区为 back hair 单独调整网格设置](../../imgs/mesh-settings.webp)

*选中 back hair 后，右侧面板显示该部件自己的边缘、点位密度与填充参数；画布上的高亮线框即当前结果。*

这些设置随项目状态和 Agent 工作区保存；更改会使相关网格缓存失效并重建预览。`meshTrace` 是全局设置，与网格单位一样记录在网格生成基线中；切换它按全局网格设置变更重建并迁移网格。“包裹”与其他形状参数一样有全局默认 `meshWrap` 与单层覆盖 `meshOverrides.<id>.wrap`；值为 0 时两处都不写出该字段（旧工程的设置文本与网格基线不变，没有该字段读作 0），非 0 的全局值记录在网格生成基线中，修改同样走全局或单层网格设置的重建与拓扑迁移。已有单层覆盖保存的是完整设置，其 `wrap` 不随全局值变化。
