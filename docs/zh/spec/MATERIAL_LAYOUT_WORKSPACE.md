# 素材与 Layout 工作区（设计中）

[文档目录](../../README.md) · [PSD 素材与命名](PSD_LAYER_SPEC.md) · [文档层](DOCUMENT_LAYER.md) · [图层流水线](LAYER_PIPELINE.md) · [工程格式](PROJECT_FORMAT.md) · [路线图](../ROADMAP.md)

本页是**设计稿**，尚无实现。范围是**基础 Layout**：素材、摆放、语义标签，以及"先摆放、再生成、可以反复添加和再生成"的 Rig 生成流程。对齐、抠图、补全等依赖外部 AI 的功能不在本期，见 [Layout 的 AI 辅助](LAYOUT_AI_ASSIST.md)。

## 要解决的问题

1. **生成太早。** 现在导入 PSD 的同一步就生成了 Rig（`WorkspaceSourceImporter.install` → `WorkspacePreviewBuilder.build`），工程里不存在"有图、还没生成"的状态。想先把图摆好、补齐部件再生成，只能在工程外用别的软件做。
2. **之后加的图不会被生成器认领。** 生成后用 `layer_import_images` / `layer_add_from_asset` 加入的图层是"用户网格"（`canvas_mesh_create`），永远是 `PRESET/UNKNOWN`，没有眼、嘴、头发、变形器规则，事后改分类也不会变成生成部件。
3. **分辨率被画布绑死。** PSD 里每层的像素就是画布像素，小部件只有几十像素。工程底层已经把"画布矩形"和"栅格分辨率"分开（[逐层尺寸](DOCUMENT_LAYER.md#逐层尺寸)），但没有一条主流程让用户按部件选分辨率。
4. **分类是固定枚举。** 图层的"类型 / 部件 / 侧别"是 `LayerType` + `SemanticTag`（31 个值）+ `Side` 三个枚举，界面是三列下拉；无法表达"后发里的侧发"之类的组合，也无法挂用户自己的标记。
5. **没有素材管理。** 工程里的图只有"已经是图层"一种身份；现有 `asset_*` 素材只支持 PNG，且每个素材绑在一次配准上，没有名字、文件夹，GUI 里也没有入口。

## 总体方案

- **素材**是工程内的素材库：文件夹树 + 素材条目（位图、分层图、矢量图）。素材面板像 UE 的内容浏览器或 PR 的项目面板。
- **Layout 就是源图层本身**：把素材拖到画布上，就是在 `WorkspaceDocument.source` 里增加一个引用该素材像素的源图层，画布矩形决定它在画布上的位置和大小。不另建一份与源图并行的 `LayoutDocument`，也不需要"发送"这一步：源图层已经是 Layout。
- **生成变成显式的一步**：文档带一个**生成快照**，记录"上一次生成用了哪些图层、各自的标签与几何"。摆放、加图、改标签只改当前源图，不动 Rig；用户点"生成 / 重新生成"时，生成器按当前源图重新生成，并用现有的三方合并保留用户编辑。
- **语义标签**取代"类型 / 部件 / 侧别"：每个图层一组标签，生成器认识其中一部分，其余是用户自己的标记。
- 编辑器的"选择"模式改名"物体"模式，作为 Layout 的主要操作模式。

这样，导入 PSD 只是"把 PSD 读成素材，按原位置全部摆上，再生成一次"的快捷方式；旧流程的结果不变。

## 素材

### 素材类型

| 类型 | 来源 | 在素材面板里 | 像素 |
| --- | --- | --- | --- |
| 位图 | PNG、WebP、BMP、TIFF、JPEG（不透明，提示） | 一个条目 | 原样保存 |
| 分层图 | PSD；CMO3 的"只取图片" | 文件夹：PSD 图层组即子文件夹，图层即条目 | 每层是一个位图条目 |
| 矢量图 | SVG | 一个条目，带"纹理分辨率"设置 | 按设置的尺寸栅格化后进入纹理集 |
| 文件夹 | 软件内新建 | 文件夹 | — |

- **PSD**：读成文件夹树，保留图层名、组路径、可见性、不透明度、混合模式、PSD 中的位置（作为默认摆放位置）。整份原文件另存一份，用于追溯。
- **CMO3**：导入时二选一：
  - **只取图片**：把模型里的分层图（`CLayeredImage`）读成文件夹，与 PSD 相同；没有分层图时取纹理集页面。
  - **完整模型**：沿用现有 CMO3 导入（`project_import_cmo3`），新建或替换工程。这条路径不进入 Layout 流程，因为 CMO3 工程没有生成器。
- **矢量图**：保存 SVG 原文，记录"纹理分辨率"（栅格化时的像素尺寸，默认按 viewBox 的 1×，可改）。画布上的大小由摆放决定，与纹理分辨率无关；改纹理分辨率等同于替换该图层的图片（见"替换"）。
- **WebP**：现有读取器只支持无损（VP8L）。有损与 JPEG 改用 Compose 自带的 Skia 解码，现有读取器保留作为无 Skia 环境的后备。SVG 同样用 Skia 的 SVG 渲染。
- 单个位图仍受 16 MP 与 64 MiB 的现有上限（`LayerSizeBudget`）。

### 文件夹与整理

- 软件内可以新建文件夹、重命名、移动条目与文件夹、删除。PSD 导入产生的文件夹与手建文件夹一样可以编辑。
- **文件夹可以导出为 PSD**：子文件夹成为图层组，位图条目成为图层；位置取条目的默认摆放位置，没有的从左上角排开。矢量图按其纹理分辨率栅格化。使用现有 `PsdWriter`。
- 被源图层引用的素材不能删除，删除时列出引用它的图层；也可以先删图层再删素材。

### 存储

- 素材库是**工程数据**，随工程保存，不依赖工程外文件。
- 像素沿用现有按内容寻址的去重栅格（工作目录 `blobs/`，归档 `assets/`），与源图层共用同一份。SVG 原文与 PSD 原文件作为不透明载荷按内容寻址保存。
- 素材库的结构（文件夹树、条目名、类型、默认摆放、SVG 纹理分辨率、来源）存在一个新的文档节点 `materials`（[工程格式](PROJECT_FORMAT.md) v2 的节点拆分），**进入历史**：删除、移动、重命名都能撤销，与摆放的撤销是同一条历史。新增素材的像素文件先暂存，提交成功后发布，失败或取消不留下文件（沿用素材会话的暂存与发布）。
- 现有 `asset_*` 工作流的 PNG 素材与 `assetCatalog` 不迁移、照常工作；新素材库与它们分开。两者以后是否合并另议。
- 旧工程没有 `materials` 节点，打开时素材库为空；已有的源图层不会被反推成素材。需要时可以"从当前源图生成素材"（每个源图层一个条目，引用同一份像素，不复制）。

### 缩略图与预览

- 缩略图按需生成，三档（约 128 / 512 / 2048 长边），放在内存 LRU 与可删除的 `cache/` 里，不参与工程身份与历史。
- 生成在后台进行，滚动几千个条目不阻塞界面；未生成时显示占位。
- SVG 缩略图按缩略图尺寸直接栅格化，不经过纹理分辨率。

## 素材面板（GUI）

一个新的停靠模块 `materials`，默认放在左侧，与层级树同列。

- **左栏文件夹树**，右侧内容区。顶部是路径面包屑、搜索框（按名称与标签）、视图切换、缩略图大小滑条。
- **视图方式**：
  - 网格：缩略图 + 名称，缩略图大小可调。
  - 列表：小缩略图 + 名称、类型、像素尺寸、引用次数、来源。
  - 大图预览：选中条目在右侧大图显示，可切换透明棋盘格 / 白底 / 黑底，滚轮缩放到 1:1 看像素。
- 引用了的条目带角标（被几个图层使用），未引用的可以筛选出来清理。
- **拖入**：从系统拖文件或文件夹到面板，导入到当前文件夹；拖到具体子文件夹即导入到那里。拖入 `.psd2live` 仍是打开工程。
- **拖出**：把条目或整个文件夹拖到画布上放置（见"摆放"）；拖到层级树上则放在指定位置下。
- **右键菜单**：新建文件夹、重命名、删除、导出为 PSD（文件夹）、设置纹理分辨率（SVG）、在画布上定位使用它的图层、替换为其他文件（更新该素材的所有引用，见"替换"）。
- 视觉沿用现有画布组件风格（`FloatingBar`、`FloatingMenu`、`NoticeBanner`），不另起样式。

## 摆放：物体模式

现有的"选择"模式改名为"**物体**"模式（界面文字与教程改名；内部枚举 `EditHierarchyMode.SELECT` 与快捷键动作 `MODE_SELECT` 保持原名，避免已保存的键位失效）。"选择"仍是这个模式里第一个工具的名字。

在物体模式下：

- **放置**：把素材拖到画布，在落点创建一个源图层，引用该素材的像素。默认大小：素材带默认摆放（来自 PSD）时用它，否则按"1 素材像素 = 1 画布单位"，超出画布时等比缩到画布内。整个文件夹拖入时保持各条目的相对位置，组结构成为源图组。
- **移动、缩放、旋转、镜像**：用现有变换框。对未生成或待生成的图层，变换改的是源图层的画布矩形（以及旋转时的 `layerTransform`），像素不重采样；对已生成的图层，沿用现有 `layer_transform`（网格跟着走），并在下次重新生成时折算回画布矩形（见"重新生成"）。
- **层序与分组**：层级树里拖动；与源图层的 `order`、`groupPath` 一致。
- **替换**：右键"替换图片"，可选素材面板里的条目或文件。画布上的位置与大小不变，只有像素与纹理集里的图块变化，与纹理集视图里的右键替换是同一个操作（`layer_replace_image`），差别只是来源可以是素材。
- **密度显示**：每个图层显示"素材像素 / 画布单位"。眼睛占 64×64 画布单位而素材是 600×600 像素时，纹理按 600×600 进入纹理集（受图集预算限制，被缩小的层明确列出）。
- 未生成的图层在画布上以整张图显示（一个四边形），没有网格与变形器；已生成的图层照常显示 Rig。

## 生成与重新生成

### 生成状态

文档多一个字段 `generation`：

| 状态 | 含义 |
| --- | --- |
| 未生成 | 只有源图与素材，没有 Rig。画布显示的是"摆放预览"：每个可见源图层一个整图四边形，按层序绘制，没有参数与变形器。所有 Rig 编辑操作返回 `WorkspaceNotGenerated`（新的 `WorkspaceFailure`），摆放、标签、素材、替换照常可用。 |
| 已生成 | 有生成快照。Rig 由快照里的输入生成，再重放用户编辑（与现在相同）。快照之后加入或改动的内容是"待生成"的。 |

旧工程没有这个字段，读作"已生成"，快照取工程现有的全部源图层（与现在的行为完全相同），不改写历史节点。

### 生成快照

生成器只读生成快照，不读当前源图。快照包含：

- **输入图层**：参与生成的源图层 ID 列表。
- **每层的语义标签与父级覆盖**：生成时的值。之后在面板里改标签，只改当前值，直到重新生成。
- **每层的几何**：沿用现有的 `generationSource`（冻结的生成输入）。替换图片、绘画时旧几何已被冻结在这里，所以 Rig 不变、只换纹理；重新生成时可以选择用新像素刷新几何。

现有的 `rig_generation_baseline` 日志条目已经保存过分类与父级快照，这里把它推广为文档字段，并与 `generationSource` 合并成一处。

### 待生成的内容

已生成之后：

- **新放置的图层**进入源图，但不在输入图层里，状态为"待生成"。它在画布上以整图四边形显示，绘制在层序对应的位置，可以移动、替换、改标签；它不进入导出（导出报告里列出"N 个图层尚未生成"）。
- **改了标签或父级**的图层：当前值与快照不同，标为"待生成"，Rig 仍按快照里的值。
- **替换了图片**的图层：纹理已更新，几何是旧的；标为"可刷新几何"。
- **删除图层**：沿用现有的 `layer_delete`，立即生效（经再生成合并移除它的网格），不需要等重新生成。
- 界面在物体模式的状态胶囊里显示"待生成 N"，点开列出各项；MCP 的检查结果返回同样的列表。

现有的"直接加入 Rig、不参与生成"的加图方式（`layer_import_images`，用户网格）保留，作为不需要生成器认领的饰品、补丁的入口；这类图层不计入待生成。

### 重新生成

"重新生成"（`rig_generate`）是一次文档编辑，一个历史节点：

1. 新快照 = 当前所有未排除的源图层、它们当前的标签与父级；选中"刷新几何"的图层用当前像素作为新的生成几何，其余沿用冻结的几何。
2. 用新快照生成基础 Rig G′。
3. 与上一次的生成结果 G、当前作者态 Rig M 做三方合并（现有 `RigRegeneration.merge`）：用户没改过的跟随 G′，用户改过的保留，新图层的网格直接采用 G′；未能干净迁移的内容进入 `issues`，与 `rig_update_generation` 相同。
4. 在日志末尾写一个固化点（现有 `rig_checkpoint`）。
5. 已生成图层上的 `layer_transform`：能用画布矩形表达的部分（平移、缩放、镜像）折算进源图层的画布矩形后清除，旋转保留为 `layerTransform`。这样摆放结果与生成结果一致，再次生成不会把图层弹回原位。

网格 ID 的稳定性沿用现有机制：已有图层的网格 ID 由 `splitDrawableIds` 固定，新图层按标签取名。第一次生成（从"未生成"到"已生成"）就是 G 为空的同一流程。

生成耗时与现在导入 PSD 相同量级（骨架烘焙冷启动约 5–7 秒），作为后台任务执行，报告进度，可取消；取消或失败不发布任何结果。

### 与现有再生成机制的关系

现在分类、生成设置、父级覆盖的修改会立刻触发再生成合并（`RigRegenerationCheckpoint`、`normalizeMeshEdits`）。改为生成快照后：

- 标签与父级的修改不再立刻再生成，而是变成待生成，由"重新生成"统一处理。这样多次修改只合并一次，也避免每次改一个标签都等几秒。
- 生成设置（网格密度、Rig 数值等）的修改仍立即再生成，行为不变。
- MCP 的 `layer_classify` 保留，语义随之改为"修改当前标签，待重新生成"；结果里返回 `pending: true`。需要立刻看到效果的调用者在同一批量里接一个 `rig_generate`。

## 语义标签

### 模型

每个图层有一组标签（字符串集合）。标签分三类：

| 类 | 例子 | 生成器 |
| --- | --- | --- |
| 部位标签 | `hair` `front` `back` `face` `eye` `iris` `white` `lash` `brow` `nose` `mouth` `open` `ear` `neck` `top` `bottom` `arm` `leg` `foot` `tail` `wings` `headwear` `eyewear` … | 认识，决定生成什么 |
| 侧别标签 | `left` `right` | 认识 |
| 用户标签 | 任意不在词表里的文字，如 `外套`、`可换色` | 不认识，只用于筛选与整理 |

- 生成器认识的组合有一张固定的映射表，映射到现有的 `SemanticTag`：例如 `{hair, front}` → `FRONT_HAIR`，`{eye, iris}` → `IRIDES`，`{mouth, open}` → `MOUTH_OPEN`。生成器内部仍读 `LayerSemantic`，约 85 处按枚举判断的生成逻辑**本期不改**，只改"枚举从哪里来"。
- 一个图层的标签对应不到任何组合时是"未识别"，与现在的 `UNKNOWN` 相同；同时对应到多个组合时按映射表的优先级取一个，并在检查结果里提示。
- 侧别：`left` / `right` 对应 `Side`，两者都没有即"双侧"。
- **变体**：现在的"开关差分 / 切换差分"（`LayerType.TOGGLE / SWITCH` 加参数名与切换序号）不是语义，单独作为图层的"差分"属性保留：`variant = none | toggle(parameter) | switch(parameter, id)`。界面上它不在标签里，而在图层检查器里单独一栏。
- 词表的显示名进 i18n（四种语言），标签本身是稳定的英文标识。

### 标签从哪里来

- **名称识别**：现有 `LayerClassifier` 的别名表改为输出标签集合（`front hair` / `前发` → `{hair, front}`，`-l` → `left`）。导入 PSD、放置素材时自动给出，用户可改。
- **素材上的标签**：素材条目与文件夹也可以带标签；放置时，条目自身的标签与它所在各级文件夹的标签合并后写给新图层。这样"把一个 `眼睛-左` 文件夹整体拖进来"，里面的眼白、虹膜、睫毛自动带上 `eye` `left`。
- **手工**：图层检查器里的标签条（可增删的芯片，带词表补全）；多选图层时可以一起加减。

### 兼容

- 旧工程的 `layerOverrides`（`{type, tag, side, parameter, switchId}`）照原样读取，读取时映射成标签集合加差分属性；旧记录不改写。新编辑写新字段。
- `art_primitive`、`rig_generation_baseline`、深度拆分记录里的分类对象同样按旧格式读取、映射。
- 网格 ID（`ArtMesh` + 标签名 + 侧别 + 序号）由映射后的 `SemanticTag` 决定，与现在逐字节相同；已有工程的网格 ID 还由 `splitDrawableIds` 固定。导出用 `ExportGoldenTool` 与上一提交逐字节对比。
- MCP：`layer_classify` 保留（参数仍是 `type/role/side/parameter/switch_id`，内部换算成标签）；新增 `layer_tag`。`workspace_inspect scope=layers` 同时返回旧字段与 `tags`。`layer_add_from_asset` 的 `semantic_tag` 字段照旧接受。

## 数据模型与工程格式

| 位置 | 新增 / 变化 |
| --- | --- |
| `WorkspaceDocument` | `generation`（状态 + 生成快照）；源图层可带 `materialId`（引用的素材条目）；`layerTags`（每层标签集合）与 `layerVariants`（差分属性），旧 `layerOverrides` 只读 |
| 新文档节点 `materials` | 文件夹树、条目（id、名称、类型、像素引用、默认摆放、SVG 原文引用与纹理分辨率、PSD 原文件引用、标签、来源） |
| 节点 `layers` | 增加 `layerTags`、`layerVariants`（schema 升级只在出现新字段时发生） |
| 新节点 `generation` | 状态、输入图层、每层标签与父级快照；`generationSource` 仍在原节点 |
| 载荷 | SVG 原文、PSD 原文件按内容寻址保存 |

- 素材条目 ID、新源图层 ID 确定性生成（`StableIds`，从请求内容派生），不用随机 UUID；需要在批量里引用的新对象在请求里给出 ID。
- 拆分 / 拼回无损（`ProjectFormatV2Test`），修订 ID 计入新字段。
- 文档身份（`WorkspaceRevisions`）计入 `materials`、`generation`、标签。

## 操作（GUI 与 MCP 共用）

所有操作走现有注册表（`WorkspaceOperationRegistry`），GUI 通过 `WorkspaceBackend` 上新增的窄接口调用同一套命令；严格 `resultSchema`，后台操作另有 `jobResultSchema`；文档修改走候选 → 重建 → CAS → 一个历史节点。

| 操作 | 种类 | 说明 |
| --- | --- | --- |
| `material_import` | 文档，后台 | 1–64 个绝对路径（文件或文件夹）导入到指定文件夹；PSD 成为子文件夹；CMO3 取 `mode: images` |
| `material_list` | 查询 | 按文件夹、名称、标签、类型筛选，`offset/limit/total` 分页 |
| `material_get` | 查询 | 条目详情：尺寸、标签、来源、引用它的图层 |
| `material_preview` | 查询 | 返回条目或文件夹合成的 PNG（尺寸可选） |
| `material_folder_create` / `material_move` / `material_rename` / `material_delete` | 文档，可批量 | 整理；删除被引用的条目返回错误并列出引用 |
| `material_tag` | 文档，可批量 | 条目或文件夹的标签增删 |
| `material_set_resolution` | 文档，可批量 | SVG 纹理分辨率；已放置的图层随之替换图片 |
| `material_export_psd` | 输出，后台 | 文件夹导出为 PSD |
| `layer_place` | 文档，可批量 | 把条目或文件夹放到画布：画布矩形或落点、父组、层序；返回新图层 ID |
| `layer_replace_image` | 文档（现有） | 新增来源 `material_id`；行为不变：位置与大小不变 |
| `layer_set_canvas_rect` | 文档（现有） | 摆放的移动缩放 |
| `layer_tag` | 文档，可批量 | 图层标签的设置 / 增删；改的是当前值，待重新生成 |
| `layer_set_variant` | 文档，可批量 | 差分属性 |
| `rig_generate` | 文档，后台 | 生成或重新生成；可选 `refresh_geometry: [layer_id]`；结果含 `issues` 与生成的网格 ID |
| `workspace_inspect scope=generation` | 查询 | 生成状态与待生成列表 |

`project_import_psd` 改为：建工程 → `material_import` → 全部原位 `layer_place` → `rig_generate`，在一个任务里完成，结果与现在相同。另加 `project_create`：建一个空的未生成工程（画布尺寸），供 Layout 从零开始。

## 工作区与教程

- 新的工作区预设 **Layout**：素材面板（左）、画布（中，物体模式）、层级与图层检查器（右）。新建空工程时默认进入它。
- 物体模式的状态胶囊显示生成状态与"待生成 N"，主操作按钮"生成 / 重新生成"用 `AccentSplitButton`（下拉里有"刷新几何"选项）。
- 教程：现有"选择模式"一课改名为"物体模式"，新增"素材与摆放"一课（导入素材、拖到画布、替换、生成、再加图、重新生成）。

## 实现分期

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 1 语义标签 | 标签模型与映射表；名称识别输出标签；旧分类读取映射；`layer_tag`、`layer_set_variant`；检查器标签条；`workspace_inspect` 返回 `tags` | 现有测试全过；所有示例 PSD 的生成结果与导出逐字节不变（`ExportGoldenTool`）；旧工程打开后分类不变；改标签与改旧分类得到同样的 Rig |
| 2 生成快照 | `generation` 字段与节点；"未生成"状态与摆放预览模型；`WorkspaceNotGenerated`；待生成计算；`rig_generate`（含首次生成、新图层、标签改动、刷新几何、`layer_transform` 折算）；`layer_classify` 改为待生成 | 旧工程打开、保存、重开结果不变；"未生成 → 生成"与直接导入 PSD 的 Rig 相同；生成后加图、改标签、重新生成，已有的关键形、摆动、物理、骨骼保留；历史切换与重放一致 |
| 3 素材库 | `materials` 节点与载荷；导入 PNG / WebP（含有损）/ BMP / TIFF / JPEG / PSD / CMO3 图片 / SVG；文件夹整理；标签；导出 PSD；缩略图缓存；`material_*` 操作 | 导入后保存重开无损；PSD 文件夹导出再导入，图层、组、位置一致；被引用素材不能删除；SVG 改纹理分辨率后图层清晰度变化而位置不变 |
| 4 Layout 界面 | 素材面板（三种视图、拖入拖出、右键）；`layer_place`；物体模式改名与放置交互；替换来源扩展到素材；Layout 工作区预设；生成按钮与待生成列表；`project_create` | 从空工程拖素材、摆放、生成、再加图、重新生成的完整流程可用；GUI 与 MCP 走同一操作；拖拽预览与提交结果一致 |
| 5 收尾 | `project_import_psd` 改走新路径；教程；文档（`MCP_AUTHORING.md`、用户指南、`PSD_LAYER_SPEC.md`、英日文同步） | 导入 PSD 的结果与改前逐字节相同 |

阶段 1 与 2 是底层重构，必须先完成；阶段 3 与 4 可以部分并行（素材库的存储先行）。

## 需要验证的场景

- 旧工程（v1 与 v2，含拆分、深度拆分、CMO3 导入）打开、保存、重开，分类、网格 ID、导出结果不变。
- 示例 PSD 导入后的 Rig 与导出，与改前逐字节相同。
- 未生成工程：摆放、替换、改标签、撤销重做、保存重开；Rig 操作被拒绝且错误类别正确。
- 已生成工程：加图、改标签、替换图片、删除图层后重新生成，用户关键形、摆动、模拟、物理、骨骼、Glue 保留；冲突进入 `issues`。
- 重新生成取消或失败不发布任何结果；提交后的迟到取消保留完整终态。
- 素材：几千个条目滚动与缩略图生成不阻塞界面；删除 `cache/` 后可重建。
- 原生分辨率：小部件用高密度素材放置后，图层栅格保持素材尺寸，4× 渲染比画布密度素材明显清晰。

## 未决问题

- 新素材库与现有 `asset_*` PNG 素材、`assetCatalog` 是否合并，以及合并时机。
- "待生成"的图层是否允许参与预览动画（现在设计为只显示静态整图）。
- 标签映射表出现歧义（同时满足两个组合）时的优先级规则，需要随词表一起定稿。
- CMO3 "只取图片"在没有分层图时取纹理集页面是否有用，还是直接不支持。
