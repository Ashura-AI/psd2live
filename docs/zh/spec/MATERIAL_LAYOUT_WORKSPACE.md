# 素材与 Layout 工作区（设计中）

[文档目录](../../README.md) · [PSD 素材与命名](PSD_LAYER_SPEC.md) · [文档层](DOCUMENT_LAYER.md) · [绘画系统](PAINT_SYSTEM_ARCHITECTURE_AND_PRD.md) · [路线图](../ROADMAP.md)

本页是**设计稿**，对应路线图中的素材与 Layout 工作区，尚无实现。目标是把"用外部 AI 拆出部件、摆好位置、再交给 Rig"的流程放进主程序：先在 Layout 里摆放与校对，满意后一键发送到 Rig，等价于导入 PSD，但保留可回溯、可增量更新的来源。

设计依据：外部 AI 辅助建模流程的实测记录（两个全身角色，各 27 与 41 层）以及通用的 Live2D 拆层惯例。那些流程的主要时间花在三处：部件对齐、被遮挡区域补画、抠图与边缘处理；反复出问题的是脸歪、接缝露底、重新导入后绑定丢失。本页的每项设计都对应其中某一类问题。

## 核心价值：部件保持原生分辨率

**这是本工作区要解决的首要问题。** 导入 PSD 时，每个图层的像素就是画布像素，所以画布有多大，小部件就只有那么点像素。1280×1280 的 PSD 里，一只眼睛可能只有 64×64 像素，放大到直播窗口必然发糊；想让眼睛清晰，只能把整张 PSD 做到巨大，所有层同步变大，身体、衣服这些用不上高密度的大面积层也跟着背上制作、出图与存储成本。

Layout 把"在画布上占多大"和"有多少像素"分开：

- 眼睛在布局里仍占 64×64 画布单位，素材可以是 600×600 像素；头发、身体等大面积层可以保持低密度。每个部件各自决定自己的分辨率，总像素按需要分配。
- 摆放里的缩放只是排布大小，不是重采样。平移、缩放、显式镜像都不改写像素；发送到 Rig 时素材像素原样成为图层栅格，摆放大小成为图层的画布矩形。被缩得很小也不影响纹理的清晰度。
- 网格按画布单位生成，不随像素数变密；纹理集按各层的纹理密度与图集预算打包。

这套机制工程里已经具备：图层的画布矩形与栅格分辨率相互独立（[逐层尺寸](DOCUMENT_LAYER.md#逐层尺寸)），素材工作流已把 1024 像素素材配准到 32 单位区域并保持 1024 像素（见 [MCP 接口](../agent/MCP_AUTHORING.md#素材工作流)），纹理密度、锁定与图集预算见[工程格式](PROJECT_FORMAT.md)的 `textureOverrides` 与 `atlas`。Layout 要补的是让它成为主流程：

- **有效分辨率可见**：每个摆放项显示"素材像素 / 画布单位"（密度），并提供密度色标视图，一眼看出哪些部件偏低。
- **预算可见**：显示当前图集预算下各部件实际得到的密度。预算不足时按 fit 缩小的层要明确列出；锁定的层不被缩小（见[文档层](DOCUMENT_LAYER.md)的图集排布）。
- **以部件为单位生成素材**：眼、嘴、饰品等小部件单独以高分辨率生成，任务包的最小尺寸按部件算，不按整图算。因此不需要为了弥补整图分辨率而超分放大；外部流程里"先放大 2 倍再缩回画布"的做法在这里不再需要。

验证以看得见为准：同一个眼睛部件，分别用 64×64 与 600×600 素材发送到 Rig，在 1:1 与 4× 放大下渲染并排对比，肉眼可见后者线条与细节清晰；发送后图层栅格尺寸仍是 600×600，没有被缩回画布分辨率。

## 验证原则：可视化优先

- **看得见的验证是第一位的。** 每一步的产出都是可以直接看的图：对比图、叠加图、误差热力图、覆盖缺口图、逐层隐藏后的露底图、多姿态渲染。部件是否通过，由人或 Agent 看图决定。
- **质量检查只负责提示。** 指标与规则（补全指标、发送前检查）给出数字与标记，每条提示附带可以直接打开的图和位置；它们不阻止任何操作，也不替代目视。数字好看而图上有问题时，以图为准；数字不好看而图上更好时（例如修复了原画缺陷），同样以图为准。
- 数字用于缩小范围、排序和让 Agent 知道该看哪里，不用于放行。

## 目标与边界

- 导入前三种入口：传统导入 PSD、导入素材文件夹、新建空素材文件夹逐步添加。三者都把内容读入工程，素材与 Layout 都在工程内，不依赖工程外文件。
- 素材可以是普通图片，也可以是分层图片（含 PSD）；分层图片在素材面板里显示为文件夹，子层各有预览。
- Layout 工作区摆放部件与参考图，可摆完整部件，也可只摆参考。摆放是**排布**，不改写像素。
- 提供自动摆放、对比辅助、抠图与边缘处理、绘画拆分，最后发送到 Rig。
- 部件按自己需要的分辨率保留像素，不受画布大小限制（见"核心价值"）。
- 验证以可视化为准，质量检查只提示、不阻止（见"验证原则"）。
- 不内置任何生图服务。与外部 AI 的往来一律走"导出任务包 → 外部处理 → 导回"，保持工具无关。主路径是让外部 AI 整部件生成，补全是必须的。
- 不改变 Rig 的重建 + 重放不变式：Layout 只是 `WorkspaceDocument` 源图的上游。

## 与现有系统的关系

工程里已经有素材工作流：`asset_prepare_reference → asset_import_png → asset_register → asset_preview_composite → layer_add_from_asset`，以及 `workspace.json` 的 `assetCatalog`、`assets/` 去重栅格和 `auxiliary/assets` 元数据（见[工程格式](PROJECT_FORMAT.md)与 [MCP 接口](../agent/MCP_AUTHORING.md#素材工作流)）。它只服务"给已有模型补一个图层"：素材是单张 PNG，配准给出画布矩形，素材像素原样成为图层栅格。Layout 工作区是这条链路的推广：配准升级为一等的摆放项，素材从 PNG 推广到分层图，加入对比、抠图、补全与发送。不另起第二套素材存储。

| 现有能力 | 与本设计的关系 |
| --- | --- |
| 素材工作流与 `assetCatalog` | 并入统一素材存储（见下）；`asset_register` 的画框、锚点、绝对变换、显式镜像成为摆放项的变换；`asset_preview_composite` 成为 Layout 的合成预览；`layer_add_from_asset` 成为"发送"的单项特例 |
| 工程里保存的原图（`source/original.psd`、`assets/`、日志图片） | 统一为素材条目，见"数据模型" |
| 逐层尺寸（[文档层](DOCUMENT_LAYER.md#逐层尺寸)） | 画布矩形与栅格分辨率已经分开；"缩放只是排布大小、纹理保留原始像素"直接落在这套机制上，发送时不重采样。素材工作流已按此执行：1024 像素素材配准到 32 单位区域，图层仍是 1024 像素 |
| PSD 导入与命名分类 | 发送沿用同一套分类器与 `-l / -r` 约定；Layout 额外提供槽位预设，发送前就能看到识别结果 |
| 绘画系统 | 像素绘制、会话撤销、`PaintSpace` 直接复用；Layout 里的绘画工具是它的入口扩展，不另起一套栅格引擎 |
| 拆分物化与重导入映射 | "发送到 Rig"的增量更新是它们的上游：按稳定 ID 对应层，而不是新建工程 |

## 数据模型

**一切放在工程内。** 不引入工程外的素材文件夹与索引。"导入素材文件夹""新建素材文件夹逐步导入"是导入入口：文件被读入工程，之后工程自包含（与现在"不依赖原 PSD 路径"一致）。素材可导出回文件夹。

### 统一的素材存储

现在工程里存原图有几处各自为政：`source/original.psd`（或 `.cmo3`）、`assets/` 去重栅格、`auxiliary/assets` 暂存素材与 `assetCatalog`、`images/` 日志图片。统一方式：

- 素材条目 `Material`：`id`（内容哈希）、种类（`IMAGE` / `LAYERED`）、尺寸、子层路径（`LAYERED`）、来源 `Provenance`。像素仍是 `assets/` 里按内容寻址的去重 PNG，不复制第二份。
- 源图层（`source` 节点里的层）、素材工作流的素材、Layout 摆放项都**按内容哈希引用素材**，不各自保存像素。同一张图被多处使用只存一份。
- `source/original.psd` 成为一个 `LAYERED` 素材（子层引用各自的栅格），保留"导入时的整份原文件"标记，用于追溯与重导入映射。
- 来源 `Provenance`：参考系标签（`FULL_BODY` / `HEAD_CLOSEUP` / `PART`）、产生它的任务包 ID、衍生关系（拆分、抠图、绘画、补全得到的素材指向其父素材）。
- 预览：三档缩略图（约 128 / 512 / 2048 长边）按需生成，放进可删除的 `cache/`，不参与身份与历史，沿用头部缓存的约定。
- 不改写旧工程：v1 与旧 v2 归档照常打开，打开时把现有 `source`、`assets/`、`assetCatalog` 映射为素材条目（读取时映射，不改写历史节点与 ID）；新写入才使用统一后的节点。节点 schema 只在用到新字段时升级。

### Layout 文档

`LayoutDocument` 是工程里的一个文档节点（新类型 `layout`），随修订进入历史，沿用[工程格式](PROJECT_FORMAT.md)的节点拆分，拆分 / 拼回无损；选择、镜头等视图状态仍放 `workspace.json`，不进入文档节点。

- 画布：宽高与背景色。
- 摆放项 `Placement`：稳定 ID（确定性生成）、素材引用（素材 ID + 子层路径）、变换、可见性、锁定、混合设置、槽位绑定。
- 变换：平移、旋转、等比缩放，另可选两轴不同的缩放（脸底层需要横纵不同比例）、镜像。变换只改排布，素材像素永不改写；与素材工作流"平移 / 缩放 / 显式镜像不插值"一致。
- 显示设置 `LookSettings`：不透明度、单色模式、混合模式（正常 / 差值 / 正片叠底），只影响显示，不进入发送结果。
- 参考项：`role = REFERENCE`，不参与发送；每个参考项可有自己的参考系，例如全身母版与头部特写各一份。
- 槽位 `Slot`：预设提供的占位（部件 `role`、侧别、层序、可选的提示词模板）。摆放项可绑定槽位，未绑定的按名称分类。
- 部件对 `PartPair`：一个"原画抠图"摆放项与一个"补全"摆放项的配对，供补全指标使用（见"部件补全"）。

绘画、拆分、抠图、补全的结果保存为衍生素材，摆放项改引用它。原素材不被覆盖，历史可回退。

所有文档修改遵循现有提交边界：纯候选 `LayoutEdits` → 单项 `LayoutCommands` 与原子批量共用 → CAS → 只追加一个历史节点；昂贵计算在锁外执行并可取消；公开操作声明严格 `resultSchema`，后台操作另声明 `jobResultSchema`；错误归到 `WorkspaceFailure`，不解析消息文本。画布拖拽预览也通过同一套命令套用待提交命令。实际新增素材与现在的素材工作流一样走辅助 CAS，不改变 Rig revision；Layout 编辑本身是文档编辑，进入历史。

## 预设与槽位

预设是一份槽位清单，不是模板图。内置两份起步：

- **半身**：后发、前发、脸、眉 / 眼白 / 虹膜 / 睫毛（左右）、鼻、嘴（张嘴素材，可另分上牙、下牙、舌头）、脖子、上衣、颈饰、手臂等。
- **全身**：在半身基础上加裙、腿、鞋、尾巴、发饰。

预设里记录的经验性约束，作为发送前检查的输入，不是硬性限制：

- 嘴部只需要提供张嘴素材（最大张口），不需要单独的闭嘴部件，嘴型由程序生成（见 [PSD 素材与命名](PSD_LAYER_SPEC.md#部件分层)）。只有闭口图时，张口无法凭几何变形恢复不存在的口腔，此时给出提示。
- 刘海比参考更遮眼时，眼白 / 虹膜 / 睫毛放在前发之上，预设提供该层序变体。
- 脖子上缘应延伸到下巴之后；腿从大腿根开始，不在腰带处截断。
- 同一 `role` 的多个层以稳定 ID 区分，界面显示"槽位 → 识别的 role → 网格名"，避免编号和网格名对不上。

## 参考系与头部特写

全身图里的脸太小，实际流程里常另出一张头部高清特写。两者是两个参考系，Layout 应一等支持：

- 一个 Layout 可有多个参考项，每个参考项有自己的显示变换与参考系标签（`FULL_BODY`、`HEAD_CLOSEUP`、`PART`）。
- 头部特写到全身的映射是一个**相似变换**。部件层摆在特写的坐标里，由映射换到画布；映射只在一个地方存一份，改映射就整体带动所有头部层。
- 这个映射的旋转应接近 0。实测中一张本身偏 1.7° 的特写，被配准带入 3° 旋转后眼线倾斜到 -4.7°，成品"脸歪"。所以映射的求解默认把旋转锁为 0，需要旋转时明确打开，并显示结果眼线角。

## 自动摆放

目标：把一个部件摆到参考图上正确的位置与大小。实测的核心困难是生成工具每次都按自己的尺度重绘：偏移十到数十像素，缩放约 0.6 到 1.4 倍。已被证明有效的手段是 SIFT 配合相似变换求解、带缩放搜索的 ECC、借用配对部件的变换、地标、镜像；也证明了数值指标会互相矛盾，必须靠叠图复核。下面在此基础上改进。

### 评分：只在"本层可见"的像素上比较

自动摆放的目标函数不应拿整层去比整张参考，因为部件的一部分被别的层遮住或是补画出来的（参考里根本没有）。

- 令 `V(p)` = 摆放后本层在布局合成中处于最上方可见的像素集合（由层序与其他层的 alpha 算出），再排除用户标记的"补画区域"。
- 评分 = 在 `V(p)` 内，本层颜色与参考颜色的稳健差（Charbonnier 或截断 L1，Lab 空间），加上本层边缘与参考边缘的距离变换项。
- 这样同一个函数既可作为优化目标，也可作为之后的验收指标和可视化热力图，不会出现"对齐置信度很高但叠图看错位"。

### 分阶段求解

1. **粗配准**：在 alpha 轮廓与边缘图上做傅里叶-梅林（对数极坐标相位相关），一次给出尺度、旋转、平移的候选，不依赖纹理。动漫图纹理少、大面积平涂，纹理特征点常常不够；轮廓与线稿更稳定。
2. **特征点**：纹理足够时（点数、内点数达标）用 SIFT / AKAZE 加 RANSAC 求相似变换，替代粗配准的结果。
3. **精配准**：在评分函数上做由粗到细的优化，例如 Powell 或 CMA-ES，自由度为平移、旋转、等比缩放，可选两轴缩放；先在低分辨率金字塔上求解，再逐级细化。每级只在上一级结果附近搜索，避免跑偏。
4. **可选学习式匹配**：LoFTR 一类稠密匹配可作为插件，不作为必需依赖。

### 配对与对称约束

- 配对部件（眼白、虹膜、睫毛、眉、耳、腿、鞋）联合求解：共享一个中线，左右变换满足镜像关系加小的残差；单边不可靠时（眼白、眉毛在实测中独立对不准）借用同侧可靠部件的变换。
- 对称轴是 Layout 的一等对象：可以由两只虹膜中心或脸底层的轮廓估计，并显示参考线。眼睛整体偏离中线 12 px 这类问题一眼可见。
- 镜像摆放：姿势不对的一侧可用另一侧镜像，镜像后按评分只微调平移，不改缩放。

### 置信度与失败路径

- 输出的不是单个数字，而是：最优评分、次优候选与最优的比值（可区分度）、评分曲面在最优点附近的曲率（沿哪个自由度不确定）。
- 低可区分度时，在界面里展示多个候选让用户选，而不是静默采用第一名。
- 评分与曲率条件不满足时直接报告"不可靠"并回到手动模式，不输出猜测值。
- 所有自动摆放结果都是一次可撤销的编辑，叠加热力图默认打开一次。

### 地标模式

选两三个点（例如下巴、两侧脸颊）做横纵不同比例的缩放，脸底层常用。地标可以吸附到轮廓上的曲率极值点，减少手点误差。

## 对比辅助

Layout 里的参考图与部件都可单独调整显示，用于人看和给 AI 看：

- **不透明度**与**单色模式**：把参考染成一个色（如青）、部件染成互补色（如红）后叠加，重合处变中性、错位处显出彩边。单色模式可选取"亮度"或"线稿"（先提取边缘），后者更适合比较线条位置。
- **差值**、**卷帘**（左右滑动分隔线）、**闪烁**（两帧快速切换）、**轮廓线**模式。
- **误差热力图**：前述评分在 `V(p)` 上的逐像素稳健差。
- **一键导出对比图**：参考 / 合成 / 差值并排，带坐标网格与编号标注的层包围盒，可直接附给 AI；对比图的内容完全由捕获的 Layout 版本渲染，不读实时 GUI 状态。
- **度量**：眼线角、两耳高度差、两侧部件对称轴偏移、头身比例，超出阈值给出提示（见发送前检查）。

## 抠图与边缘处理

### 背景用白色，不再默认绿色

实测流程用纯绿底生成再色键。改用白底更好：

- 生成工具对白底最稳，母版本身就是白底，部件图与母版的色调更一致；绿底会让工具把绿色混入发丝、半透明阴影与高光。
- 绿色必须做去溢色，且无法保留真正是绿色的内容（绿瞳、绿衣）。
- 白底的缺点是前景本身有白色（白发、白袖、白纱），与背景难以区分。解决办法见下面的"背景可选 + 连通判别"，而不是回到固定的绿色。

### 白底抠图管线

目标：得到直通 alpha（straight alpha）与去污染的前景色。

1. **确定背景**：从图像边框做泛洪，选取与背景色足够接近、且与边框连通的像素为确定背景。前景内部的白色（白发、白袖）若不与边框连通，就不会被误判为背景。
2. **确定前景**：对非背景区域做腐蚀；用户可涂抹加入或排除，应对白色前景直接接触边框、或白色区域由细线隔开的情形。
3. **未知带**：背景与前景之间的窄带。
4. **前景颜色估计**：对未知带像素，从邻近的确定前景估计前景色 `F`（多级前景估计或邻域加权，保证不引入背景色）。
5. **alpha 求解**：已知背景色 `B` 时，观测 `C = αF + (1−α)B`，则 `α = ((C−B)·(F−B)) / |F−B|²`，截断到 [0, 1]。`F` 与 `B` 接近时分母趋零，这类像素按连通判别与邻域平滑决定，不用公式。
6. **可选闭式抠图**：未知带宽、发丝多时，用闭式（Levin）或其近似求解，三值图由上面几步给出，不要求用户画三值图。
7. **颜色去污染**：未知带内输出颜色取估计的 `F`，不保留与背景混合的颜色。这是去掉白边的关键。
8. **小连通块**：面积小于阈值的残留块删除（同类缺陷实测过：3% 到 10% 的低透明度噪点会让导入把整个包围盒当成网格）。阈值与 alpha 阈值在预览里直接显示，被丢弃的像素以半透明红叠加。

### 背景色选择

生成任务包可选背景色。默认白；当部件以白色为主（白发、白袖、白纱）时，建议改用与部件最远的颜色：统计部件颜色，在候选色里取"与所有前景色距离的最小值最大"的那个，在导出任务包时提示。此时抠图管线步骤 1 的背景色取该色，其余不变。

### 双背景精确抠图（可选）

对同一个部件，若能取得白底与另一底色（如黑底）两版**像素对齐**的图，则 `α = 1 − |C_w − C_b| / |B_w − B_b|`，前景色可闭式还原。外部生成工具给不出像素对齐的两版时，这条路用不上；它只用于程序自己合成的素材（例如由 PSD 子层合成对比）。作为可选模块，不是主路径。

### 边缘处理

- 收缩 / 扩张（亚像素），羽化（高斯，半径以像素的小数计）。
- 去色边：按估计前景色重染边缘，而不是整体压暗。
- 光晕（halo）检测：边缘外圈亮度与背景差在阈值内但与前景差大，提示。
- 线稿保护：线稿像素的 alpha 不被羽化冲淡。
- 半透明素材（腮红、阴影）不走抠图：以白底出图，用"正片叠底"层导入，记录在 `Placement.blend`。

## 部件补全

**补全是必须的。** 一个部件如果只是和原画严格匹配而没有补出被遮挡的部分，对 Rig 是严重错误：转头、摆动、隐藏上层时会露底。所以评价补全结果的第一位是"补了多少"，其次才是"和原画有多像"。

### 主路径：整部件生成

一个部件由外部 AI 按提示词**一次性画出完整部件**（含被遮挡的部分），导回后抠图、自动摆放，作为衍生素材。不再把"可见像素保持不变、只补遮罩内"作为主流程。

依据是外部流程里同一个角色的两种做法的对比：

| | 手臂（袖子下被遮挡） | 腿（裙下、腰封下、两腿相贴、靴内） |
| --- | --- | --- |
| 做法 | 整部件一次生成，对齐 | 先整部件生成（观感干净），后改为"母版可见像素 + 洋红遮罩补画 + 回贴"，反复返工多版 |
| 结果 | 一次可用，只需对齐和左右镜像 | 接缝、竖棱、碎片、左右腿风格不一，补画结果多次被否 |

手臂能成功、腿失败，原因归纳如下：

1. **整体一致性**：整部件在一次生成中完成，线宽、明暗、光照、风格天然一致。遮罩补画把两个来源的像素拼在一起：一边是母版放大后的像素，另一边是生成像素，锐度、噪点、色调都不同，接缝必然可见。
2. **遮罩边界的长度与复杂度**：手臂被遮部分是袖口下的一小段，边界短而规则（一个圆柱的截面），生成端只需延长一个凸形。腿的遮罩边界又长又不规则（裙摆、腰封、吊袜带、膝盖贴合处、靴口），生成端要在每一处与既有像素严丝合缝，且生成工具并非真正的局部重绘，输出会被整体重绘、缩放和平移，回贴时边界错位。
3. **被遮部分是否会被看见**：手臂顶端永远在袖子里，即使被截平也不可见，是"无关紧要区"。大腿根在隐藏裙子或摆动时会露出来，是"必须正确区"，截断和渐隐立即暴露。
4. **形状先验**：手臂是单一材质的凸管，模型有很强的先验。腿同时有半透明丝袜、吊袜带、挂饰、裙摆投影，每个都是不同材质，一张遮罩里混着多种语义。
5. **可见像素里混着别的层的内容**：母版上的裙摆投影、吊袜带勒痕是上层对腿的影响，保留在"可见像素"里就成了腿层的一部分，动起来跟着腿走。
6. **任务切分爆炸**：为了避免两腿画到一起，要按腿、按遮罩拆成多个任务，每个任务再来回试不同工具，最后左右腿来自不同的生成器，风格不一致。
7. **度量指向了错误目标**：交付时以"可见像素与母版逐像素一致率 99%"为验收，但观感问题出在接缝和补画区，而这个指标看不到它们。
8. **内容审核**：孤立的腿部裁切加遮罩更容易被拒绝，整图上下文加"完整部件"的请求通过率明显更高。

结论：整部件生成作为主路径；遮罩补画降级为局部修复工具（见下）。整部件生成并非没有缺陷，实测里出现过的有：姿势与母版不同（改用另一侧镜像）、完全看不见的部件尺度不准（手摆矩阵）、顶端被画成一条直线截断（提示词要求补到根部并画出自然的收口）。这些由自动摆放、镜像与提示词修订处理，不需要回到遮罩路径。

### 部件的拆分方式

任务按**语义与材质**拆分，而不是按遮挡区域拆分：

- 腿：肤色大腿 / 丝袜 / 吊袜带与挂饰 / 靴，各是一个部件，各一次生成，各自在 Layout 里叠放。一次生成内不要混多种材质。
- 成对部件每个任务只含一侧，另一侧不入画。左右对称的可用一侧镜像，再微调。
- 参考用带上下文的整图或较大的裁切，让模型理解部件在人物中的位置；要求输出里只有该部件、纯白背景。
- 上层对它的影响（投影、勒痕）不应出现在部件里，提示词明确要求。

### 任务包

对每个部件任务生成一个目录：参考图（原画，含上下文）、`part.json`（部件、侧别、槽位、画布尺寸、背景色）、提示词模板（含预设的补全要求：补到根部、有自然收口、无投影）、可选的"原画抠图"素材。外部处理后导回一张整部件图。

### 导回

1. 白底抠图（见"抠图与边缘处理"）。
2. 自动摆放到原画上（评分只在可见重叠区进行，见"自动摆放"）。允许比原画更好：对齐只用相似变换，不强行把新图的轮廓拉到原画上。
3. 可选的低频色彩匹配：只用重叠区域的低频颜色差校正整体偏色，保留生成图自己的高频细节，不替换像素。
4. 作为衍生素材入库，与原画抠图建立 `PartPair`。

### 两项指标

对一个 `PartPair`（原画抠图 `O`、新图层 `N`，均已摆放到同一画布坐标）计算，作为 MCP 与 GUI 共用的读取操作返回。

**重叠区域：原画重合度 `overlap_fidelity`**，范围 0 到 1。衡量新图层在原画可见区域上与原画有多接近。

- 逐像素相似度 `s(p) = exp(−ΔE(p)/ΔE₀)`：`ΔE` 在 Lab 空间，比较前对两者做同样的小半径模糊，并在 ±2 px 内取最近邻，避免亚像素偏移被重罚；线稿像素按边缘距离额外比较。
- `overlap_fidelity = Σ min(αO, αN)·s / Σ αO`。同时返回分量 `coverage = Σ min(αO, αN) / Σ αO`（原画可见部分被新图层覆盖了多少）与 `color_similarity`。
- 不是越接近 1 越好：原画本身有缺陷（线条抖动、色块、残留的投影）需要修复时，降到约 0.7 可能更好。所以它只是参考，不阻止任何操作；是否接受由看图决定，用户或 Agent 可设自己的提示下限。

**新图层总体积：原画 `completion_ratio`**，须大于 1。

- `completion_ratio = Σ αN / Σ αO`（二维下"体积"即 alpha 质量）。
- 部件有被遮挡的部分时，补全后必须大于 1；接近 1 说明只是在复述原画，没有补全。
- 不是每个部件都应该超过 1：完全没有被遮挡的部件（例如孤立的饰品）可以等于 1。用 `hidden_boundary_fraction` 判断：原画抠图轮廓中，紧贴上层图层边缘（而不是紧贴真背景）的比例。比例高而 `completion_ratio ≈ 1`，给出 `NOT_COMPLETED` 提示（最醒目的一条），并附上原画轮廓中贴着上层的位置图，由人看图确认是否真的需要补。部件可显式声明 `fully_visible` 豁免。

配套的诊断（同一操作返回）：

- `hidden_gain`：新增面积中落在上层图层之下的部分，占 `Σ αO` 的比例，是合理的补全。
- `visible_spill`：新增面积中**没有**被上层覆盖、因此会改变合成观感的部分。大于零时合成图与原画不同，需要确认是修复还是漂移。
- `composite_fidelity`：用新图层替换原画抠图后，整体合成与参考的相似度。部件之间没有露底、没有风格割裂时接近 1。
- `style_drift`：新增区域与原画区域在风格统计上的距离（调色盘分布、边缘梯度直方图、线宽分布，可选图像嵌入的余弦距离）。新图层可以比原画更好，但风格不能迁移，这项用来提示去看。
- `seam_score`：新增区域与原画区域交界处的颜色与梯度突变。

返回结构（`resultSchema` 严格声明）：

```
{ pair_id, overlap_fidelity, coverage, color_similarity,
  completion_ratio, hidden_boundary_fraction, hidden_gain, visible_spill,
  composite_fidelity, style_drift, seam_score,
  flags: [ { rule, level, detail, evidence? } ],
  images: { compare_sheet, overlay, heat, ... } }
```

`flags` 的 `rule` 与等级由规则枚举确定（见"发送前提示"），不由本地化文本推断；`evidence` 指向可以直接看的图与位置。`images` 与数字一同返回，Agent 应当先看图再解读数字。

### 局部修复（遮罩补画）

仍保留，用于小范围缺陷：一个接缝、一块污点、一小块露底。流程是任务包（背景色底 + 可见像素 + 保留色遮罩）→ 外部处理 → 导回，遮罩外像素不被改动，遮罩内取生成像素，窄带边界融合。它是硬约束的局部工具，不用于补出整个部件。导回前先在遮罩外区域标定配准，并校验遮罩外是否被改动、遮罩内是否残留保留色。

**不在遮罩内做模糊或取色填充冒充生成**：外部工具有时会这样交付，所以导回只信图像生成的像素，必要时取其中间轮次的原始生成图。

## 绘画与拆分

继续使用[绘画系统](PAINT_SYSTEM_ARCHITECTURE_AND_PRD.md)的栅格引擎与会话，工具增加：

- 选区：套索 / 魔棒（带容差与连通）/ 矩形，加减与羽化。
- 克隆、涂抹、修复笔，用于人工细节修复。
- 对称绘画：沿 Layout 对称轴镜像笔画。
- 图层拆分：
  - 按 alpha 列最小处拆成左右两半（成对部件）。
  - 按连通块拆分。
  - 沿手绘线拆分。
  - 拆出的子层各自成为衍生素材，保留与原素材的关系。
- 合并与整理：合并若干层为一个素材，保留原图以便还原。

## 发送到 Rig

发送是一个事务：读取 Layout 的捕获版本 → 构造源图层 → 提交到 `WorkspaceDocument`，经候选、CAS、单个历史节点。

### 发送前提示

发送前先看图：多姿态渲染、逐层隐藏后的露底图、覆盖缺口图、对比图都应当在发送前后打开看过（见"验证原则"）。下面的检查只负责提示，帮助缩小范围，**不阻止发送**，也不替代目视。

沿用质量检查的做法：规则枚举唯一确定等级与类别，不从本地化字符串推断等级；但这里没有放行栅栏（`fence`），所有等级都放行。等级只有 `warning`（建议先看一眼）与 `info`。每条提示附带证据：对应的图与位置，点击即可在 Layout 里定位。

| 规则 | 等级 | 说明 |
| --- | --- | --- |
| `UNRECOGNIZED_ROLE` | warning | 层没有绑定到槽位且名称无法分类（仍可发送，导入后按未知类型处理） |
| `DUPLICATE_SLOT` | warning | 同一槽位被多个摆放项占用，且不是预设允许的多层 |
| `HEAD_TILT` | warning | 眼线角超出阈值（默认约 1°） |
| `AXIS_OFFSET` | warning | 配对部件整体偏离对称轴 |
| `PAIR_SCALE_MISMATCH` | warning | 配对部件缩放比相差过大 |
| `MOUTH_OPEN_MISSING` | warning | 有嘴部层但没有张嘴素材，张口时无法露出口腔、牙齿；只有张嘴素材、没有闭嘴部件是正常的，不提示 |
| `ALPHA_BBOX_NOISE` | warning | 层包围盒远大于有效内容，通常是低透明度噪点；附预览 |
| `EDGE_FRINGE` | warning | 检测到背景色边或光晕 |
| `COVERAGE_GAP` | warning | 若干层的 alpha 并集未覆盖参考的前景，指出缺口位置（实测里两侧大腿遮罩互相排除，大腿根中间出现空隙） |
| `SEAM_EXPOSURE` | warning | 依次隐藏某层后参考前景露底的位置，用于提前发现颈部、袖口、袜口接缝 |
| `NOT_COMPLETED` | warning | 部件有被遮挡的边界，但 `completion_ratio` 近似 1，没有补全；这是最需要看的一条，部件可显式声明 `fully_visible` 豁免 |
| `VISIBLE_SPILL` | warning | 新增面积落在未被上层覆盖处，合成观感与原画不同 |
| `STYLE_DRIFT` | warning | 新增区域与原画区域的风格统计距离超阈值 |
| `LOW_FIDELITY` | info | `overlap_fidelity` 低于用户设定的下限；原画有缺陷时较低可以是合理的，仅提示 |
| `LOW_DENSITY` | info | 部件的有效分辨率（素材像素 / 画布单位）低于同类部件或图集预算把它缩小了；对应"核心价值"里的密度视图 |
| `LAYER_ORDER` | info | 层序与预设变体不同，例如眼睛不在前发之上 |

`COVERAGE_GAP` 与 `SEAM_EXPOSURE` 是把实测里"隐藏裙子看大腿""低头看脖子"的人工渲染检查变成可以直接看的图：只需 alpha 并集与参考前景，不需要生成 Rig。图本身比提示重要，提示只是告诉你该打开哪几张。

### 增量更新

实测中最大的痛点是重新导入每次新建工程，手动加的 swing、物理、腿部参数全部丢失。发送必须避免这一点：

- 每个摆放项有稳定 ID，发送时写入源图层的来源映射 `sourceOrigin = layout:<LayoutId>/<PlacementId>`。
- 首次发送：创建工程，等价于导入 PSD。
- 再次发送：按来源映射匹配现有源图层，**替换像素与变换，保留 Rig 编辑覆盖层**。新增摆放项增加源图层，删除的摆放项把对应图层标为"待确认"，不静默丢编辑。
- 匹配不到的、被拆分或合并过的源图层，沿用既有的重导入映射与拆分物化机制（见[文档层](DOCUMENT_LAYER.md#拆分物化画元记录-art_primitive)），并在发送报告里逐项列出。
- 发送结果写入单个历史节点，可撤销。

### 变换如何落地

- 位置与缩放写入源图层的画布矩形，栅格保持素材的原始分辨率，网格按画布单位生成，即走既有的逐层尺寸路径。
- 旋转和两轴缩放同样落在矩形与采样方式上；不能用矩形表达的组合（旋转 + 剪切）发送时才烘焙成新栅格，并在报告里标明哪几层做了烘焙。
- 镜像在摆放项里是显式属性，发送时翻转栅格，同样记录来源。

## MCP 与 GUI

素材浏览、Layout 编辑、自动摆放、抠图、部件任务包、补全指标与发送都是公开操作，GUI 与 MCP 走同一套命令（见 [MCP 接口](../agent/MCP_AUTHORING.md)）。

接口设计吸取实测里的槽点：

- 参数命名一致（同类操作用同一个字段名表示目标 ID / 操作名）。
- 列表分页统一使用 `offset` 与明确的总数，不引入未说明的游标。
- 引用对象的名称写法在读写两个方向完全一致，不要求调用者去掉或加上前缀。
- 长任务返回任务句柄，等待时长上限写进 schema。
- 读取走捕获会话，结果来自捕获版本。
- 补全指标是只读查询，请求给出 `pair_id` 或原画抠图与新图层的两个摆放项 ID，返回上文的结果结构，其中包含对比图、叠加图与热力图。Agent 先看图，再参考数字决定接受、重做或局部修复；数字只是提示，不构成放行条件。
- 可视化检查（对比图、覆盖缺口图、逐层隐藏图、多姿态渲染、密度色标）都作为只读操作公开，结果图可重复获取。

| 1 | 统一素材存储（`source`、`assets/`、素材工作流并入；旧工程读取时映射）；预览金字塔与 PSD 子层；Layout 文档与基本摆放；槽位预设；首次发送到 Rig | 同一份摆放发送后与等价 PSD 导入的 Rig 一致；Layout 往返保存无损；旧工程保存重开后素材与图层像素不变；**64×64 画布单位的部件使用 600×600 素材发送后，图层栅格仍是 600×600，4× 渲染明显比 64×64 素材清晰（并排对比图）** |
| 2 | 对比辅助（不透明度、单色、差值、卷帘、对比图导出）；对称轴与度量 | 导出的对比图由捕获版本渲染，与界面一致 |
| 3 | 白底抠图与边缘处理；小连通块与 alpha 预览 | 合成白底再抠回，F 与 α 误差在阈值内；无白边 |
| 4 | 自动摆放（粗配准、精配准、配对约束、置信度与候选） | 用已知变换扰动的合成数据，恢复误差达标；低可区分度时不静默采用 |
| 5 | 部件任务包与整部件导回；补全指标（两项加诊断）与 `NOT_COMPLETED` 等提示；局部修复（遮罩补画） | 指标在合成数据上符合预期（复述原画 → `completion_ratio ≈ 1`；补出被遮部分 → 大于 1；缩放平移后的结果仍能配准）；局部修复遮罩外像素不变 |
| 6 | 发送前提示（含可视化检查图）与增量更新 | 二次发送保留 swing、物理与关键形编辑；提示不阻止发送，每条提示附图 |
| 7 | 绘画选区、克隆、拆分、对称绘画 | 与绘画系统共用会话与撤销 |

阶段 3、4、5 彼此独立，可按需要先后调整。阶段 1 与阶段 6 的发送语义须在第一次发送前就按稳定 ID 设计，否则后补增量更新要迁移工程格式。

## 需要验证的场景

- 摆放项的变换、层序、混合设置的保存恢复、撤销重做与历史切换后一致。
- 拖拽预览与提交后的结果一致，取消不留中间态。
- 白底抠图：白发与白袖不被抠空；细发丝半透明处无白边；背景噪点被清除。
- 自动摆放：在合成扰动数据上恢复变换；对称部件左右一致；失败时不输出猜测值。
- 补全指标：原画抠图自身 → `completion_ratio = 1`、`overlap_fidelity = 1`；补出被遮部分的合成结果 → 比值大于 1；故意改动风格的结果 → `style_drift` 升高；有修复意图的结果 `overlap_fidelity` 降低但不报错。
- 局部修复：模拟被缩放、被平移的结果能配准；遮罩外像素不变；保留色无残留。
- 原生分辨率：小部件用高于画布密度的素材时，摆放缩放、移动、镜像不改变像素；发送后图层栅格尺寸等于素材尺寸；图集预算不足时，被缩小的层在密度视图里可见。
- 发送：首次与再次发送的 Rig 一致；再次发送不丢失编辑；被删除的摆放项给出确认而非静默丢失。
- 对比图导出：内容来自捕获版本，不读未提交的 GUI 值。
- 大量素材：几千个条目的滚动、预览生成不阻塞 GUI；删除 `cache/` 后可重建缩略图。

## 未决问题

- 补全指标的阈值：`completion_ratio` 的 `NOT_COMPLETED` 判定与 `hidden_boundary_fraction` 的下限，需要用真实部件（手臂、腿、尾巴）标定。
- `style_drift` 是否使用图像嵌入，还是只用调色盘 / 边缘 / 线宽统计。
- 学习式抠图与匹配（BiRefNet、LoFTR 等）是否作为可选插件，以及模型分发方式。
- 单色模式的默认配色，以及对色觉差异用户的替代方案。
- 跨工程复用素材（把一个工程里的素材拿到另一个工程）的入口：只复制，不共享引用。
