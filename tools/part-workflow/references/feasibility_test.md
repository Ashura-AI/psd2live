## 步骤与通过条件

### E1 原画抠图与上层
- 在母版上目视估计每个部件和其上层的多边形，`cutout --preview` 看描边叠加图，反复修正到贴合。
- 通过：预览图上描边贴着真实轮廓，没有明显漏掉或多出的区域（肉眼）。记录迭代次数。

### E2 任务包与生成
- `task` 生成任务包（含 `--original`、`--upper`）。看 `prompt.txt` 是否合理，必要时用 `--rule` 追加规则。
- 生成并**逐张看图**：姿势是否与母版一致、风格是否一致、被遮挡的一端是否补全且自然收口（无直线截断、无渐隐）、背景是否纯白、是否混入别的部件、是否按要求只画一侧。
- 通过：每个必做部件至少有一张在这些点上"基本可用"的结果。不可用的也保留，作为指标检验样本。

### E3 抠图
- 对每张结果跑 `ingest`（它会先抠图），查看 `candidate.png`（叠在深色背景上看）。
- 通过：`bbox_fraction` < 0.6、`touches_border` 为 false；肉眼看无白边、无背景残留、细节（袜口、手指、袖口等）不丢；被线条包住的内部白色保留。
- 记录：生成工具是否真的给出纯白背景；背景有渐变/噪点时抠图表现。

### E4 对齐
- 通过：`ambiguous` 为 false，或经 `--init`/范围调整后确认；`sheet.png` 的单色叠加里可见区域大致重合（青/红边在亚像素到数像素内）；缩放在合理范围。
- 记录：自动对齐是否一次成功、需要手工干预的次数、对齐耗时。
- 另做一个负面检查：把一张已对齐的 `placed.png` 手工平移约 20 px 并缩放约 8%（用几行 Python 即可）后跑 `metrics`，确认 `overlap_fidelity`、`visible_spill` 明显变差，说明指标对错位敏感。

### E5 指标
- 对每张候选运行 `metrics`（`ingest` 已含）。必须包含：
  1. 至少一张"补全良好"的候选；
  2. **复述原画**的对照：把 `original.png` 当作新图层跑 `metrics`，应出现 `NOT_COMPLETED`；
  3. 至少一张有问题的候选（缩放错、风格变、截断等）。
- 通过：
  - 补全良好的候选：`completion_ratio` > 1.1，未被阻止；
  - 复述原画：被 `NOT_COMPLETED` 阻止；
  - 有问题的候选：至少有一项 flag 或明显更差的指标，且与你目视的判断一致。
- 记录：各候选的指标表、你目视的"可用/不可用"、指标是否与目视一致；有哪些误报与漏报；建议的阈值调整。

### E6 装配与检查
- 把 P1、P2（及 P3）的 `placed.png`，加上上层（袖子、裙子、靴子等抠图）和一张母版背景层（可选，作为最底层），写 `spec.json`。
- 运行 `composite --hide <上层>`：隐藏上层后看被遮挡部件是否完整（手臂上端、袜子顶端的收口，无截断、竖棱、碎片）。
- 运行 `exposure`：看隐藏上层时的洞。运行 `psd` 写出 PSD（需要 psd-tools），确认层名、层序、数量。
- 通过：隐藏上层后看到的部件是完整的，没有明显缺口。

### E7（可选对照）局部修复 vs 整部件
- 对 P2 在大腿根（裙下）选一块区域，做一次 `repair-task` → 生成 → `repair-paste`，与整部件生成的同一区域并排比较接缝与风格一致性，验证"整部件生成优于遮罩补画"的判断。只做一次，不追求调好。

## 报告

在工作目录写 `report.md`，包含：

1. 环境与版本；selftest 结果。
2. 部件表：部件、尝试次数、采用的结果、`overlap_fidelity`、`completion_ratio`、flags、对齐是否一次成功、目视判断。
3. 每个部件的图：`sheet.png`、隐藏上层渲染、必要的放大图（给出路径）。
4. 逐项回答：
   - 白底抠图在真实生成图上是否可靠？哪些情况失败？
   - 生成工具是否遵守纯白背景、只画一个部件、补全被遮挡部分、不画上层的影响？
   - 自动对齐的成功率、失败模式、需要的手工干预。
   - 两项指标是否与目视一致？误报与漏报？阈值建议。
   - 整部件生成 vs 局部修复（E7，若做了）的观察。
   - 流程耗时（每步）。
5. **工具缺陷清单**：每条给复现命令、现象、期望、你认为的原因。允许你直接修小缺陷，但每个改动都要列在报告里（文件、改了什么、为什么），并重新跑 `selftest`。
6. **结论**：GO / GO with changes / NO-GO，各给证据。以及下一步建议（需要补的工具、需要标定的阈值、需要人决定的事）。
